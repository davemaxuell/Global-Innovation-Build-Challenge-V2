# Replacement post-training implementation

The active `scripts/run_pipeline.py` now runs the SOTA-method study described in `POSTTRAINING.md`. The default configuration is `configs/posttraining_sota/default.json`; the historical entry point is `scripts/run_legacy_pipeline.py`.

Implemented: a versioned protected task registry; strict content verifiers; mixed raw/chat response-only SFT and raw replay; own-policy preference generation with diversity gates; DPO and matched-positive control; fresh-policy GRPO-style updates with exact reference KL; training-only curriculum; raw answer and suffix likelihood evaluation; three-seed selection; one-use confirmation with overlap protection; unchanged required benchmark execution; lineage, compute accounting and portable candidate packaging.

Validation: **212 CPU tests passed**; the one GPU-only test skipped by the CPU suite passed separately on the allocated H100. The actual 46,346,752-parameter model passed a disposable kernel smoke test. Exact GPU restart reproduced identical weights, replay cursors and counters. Relocated package verification and offline inference passed. The smoke's synthetic preference/reward diagnostics are not production training data or quality evidence. Actual sampled task rewards in that short smoke were zero, so it does not demonstrate RL readiness.

Prepared data: **118,429 train examples**, **7,862 development**, and **7,862 confirmation**. Both held-out primary panels exceed 500 examples and 50 source/fact-world groups per domain. The balanced two-epoch inventory permits **1,715,410 supervised response targets**; the nominal four-million setting is a ceiling. Generic generated-template n-grams are exempt only between disjoint generated worlds; natural data, raw replay, exact prompts, prior exposure and benchmark protection remain enforced. Semantic decontamination is not certified.

Implementation adaptations: FP32 behavior/reference/RL scoring keeps sampled and rescored log probabilities consistent; SFT remains BF16 on CUDA. QASC's supplied supporting facts provide short SFT demonstrations, not an external teacher or a learned/verifier prose reward. Gradient and crash/recovery tests are executable; real task gains still require the registered study.

The study was launched in tmux **gibc-post-sota**, restricted to the registered physical GPU 0 UUID, through local packaging. Its first stage is base development evaluation, followed by the SFT pilot matrix. Preference/RL stages can be skipped by their preregistered gates. The old base weights and release are intact. No new candidate has been claimed as better, confirmation has not been scored at launch, and no external publication/upload was performed.

Records: `artifacts/posttraining_sota_verification/IMPLEMENTATION_VALIDATION.json`, `artifacts/posttraining_sota_v1/registration.json`, `experiment_matrix.json`, `launch.json`, `status.json` and `runner.log`. All earlier pipeline files, checkpoint histories and completed releases remain available; obsolete unlaunched data drafts were removed after preserving their audit manifests.

Monitor with `python scripts/run_pipeline.py status` or `tmux attach -t gibc-post-sota`. After an interruption, resume with `python scripts/run_pipeline.py run`. A completed stage or implementation test is not evidence of improved competition performance; only the fixed selection and benchmark records support that claim.
